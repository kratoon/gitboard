- **Question:** Is the per-user profile (remotes, preferences, personal saved views, commit identity) required to be a Git repository, and may the local CLI adopt it as its registry? Is the proposed split of settings right?
- **Why it matters:** It decides where each setting lives and whether per-user configuration is portable between instances and devices. A format decision (`profile.yaml`, new optional `boardBranch` key in the repository config) is hard to change once users have data.
- **Options:** Profile as Git-backed repository, as an instance-local file, or both with the same schema. CLI: keep `repos.json`, or adopt the profile later via a `gitboard profile` command. Split: repository (projects, columns, views offered, default board branch), profile (repositories, per-user branch override, visible projects, default repository, view, theme, personal saved views, identity), instance (listen address, auth, limits, allowed remote hosts), secrets (never in Git).
- **Recommendation:** Optional, Git-backed or local with the same schema; CLI adoption later. Adopt the split above. Shared saved views, if built, live in `.gitboard/config.yaml` (FEAT-cd7b875); personal ones in the profile.
