## Context

"Done" matters in three places: the backlog hides finished work (ADR-0014), epic progress counts finished
children (ADR-0010), and the UI shows which columns are finished. All of them assumed that **the last column is
done**. That is wrong for the `ADR` project, whose last column is `rejected` while `superseded` is just as
closed, and for any workflow with more than one closing state (`merged` and `dropped`, for example). This
resolves the open question about what counts as done (OQ-85a6d2c).

## Decision

**A column can say whether it is done**, with `done: true` or `done: false` next to its `id` (and `name`):

```yaml
projects:
  - key: ADR
    name: Architecture decisions
    columns:
      - id: proposed
      - id: accepted
      - id: superseded
        done: true
      - id: rejected
        done: true
```

- **Resolution.** If any column in a list states `done` (true or false), the done columns are exactly those
  with `done: true`, so unmarked columns are not done. If no column states it, the last column is done when the
  list has more than one column. That is how every config written before this flag behaves, so nothing needs
  migrating. The built-in columns mark `done` as done.
- **Any number of done columns**, including none (state `done: false` on every column).
- **Layering is unchanged (ADR-0011):** a project's columns replace the repository's, flags included.
- **Where it applies:**
  - The backlog hides every done column unless `includeDone` / `--all` / "Show done" is used; its data lists
    them as `doneStatuses`.
  - Epic progress counts children in any done column.
  - Columns resolve with a `done` field everywhere (`columns show`, `board`, `backlog`), the CLI marks them
    `[done]`, and the board and backlog show a check mark on done column headers.
  - Moving an issue into a done column has no other effect.
- **Command line.** `--done a,b` on `init`, `project create` and `columns set` lists which of `--columns` are
  done; the others are explicitly not done. When columns are re-set without `--done`, a column whose id is
  unchanged keeps its done flag and any custom display name, so reordering never changes what counts as done;
  new columns are not done once some column says so.
- **Web UI.** The Columns dialog has a "Done columns" field; saving states every flag explicitly.

## Alternatives considered

- **A `doneStatuses` list next to `columns`:** two places to keep in sync, and renaming a column would break
  it. The flag lives with the column.
- **Keep "the last column is done":** simplest, but wrong for the `ADR` project and for multi-state endings.
- **Require the flag and drop the fallback:** breaks existing configs for no real gain.
- **A separate "closed" notion in addition to done:** nothing needs it today.

## Consequences

- Existing repositories behave exactly as before until someone sets a flag.
- Mixed lists are easy to misread: as soon as one column says `done`, an unmarked last column is no longer done.
  The Columns dialog and `columns show` always show the resolved result.
- `backlog` JSON changes shape: `doneStatus` became `doneStatuses` and `Column` gained `done`. The backlog is
  new in this release cycle, so nothing external depends on the old field.
- The implicit "last column" rule can be retired later if every config is made explicit.
