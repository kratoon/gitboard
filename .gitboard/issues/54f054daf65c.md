- **Goal:** prepare core for per-user hosting without changing any local behaviour.
- **Includes:** an explicit resolver context (registry source and clone directory) instead of process-global `userDirs()`; hardened `runGit` defaults (no global or system config, hooks disabled, protocol restrictions, timeouts, allow-listed environment, no user value in `GIT_SSH_COMMAND`, option-injection validation of URLs, hosts and branch names); HTTPS remotes with an allowed-hosts list and private-address blocking, only in hosted mode; hosted clone options (treeless, cone sparse checkout of `.gitboard/` in sparse-index mode); `core/git/sync.ts` (fetch, fast-forward, commit only `.gitboard/`, push, reset to remote, trailers); an opt-in `gitboard sync` for CLI users; a summary projection for board and backlog responses (see the dedicated issue).
- **Also:** a top-level `branch` key in the repository config with a `validate` check (absent or equal to the branch it is on, and a warning when issue files exist on a branch whose config points elsewhere) and a guard: write operations on a branch whose config has `branch` pointing elsewhere fail with an error naming the board branch and the worktree command (reads print a hint), so a write can never silently land where the hosted app does not look; split `repo.init` from registration in the local registry so hosted mode can init without registering.
- **Depends on:** phase 0 results; ADR-0aa6b23.
- **Validation milestone:** all existing tests and the parity test unchanged; new sync tests against a local bare remote.

- **Related:** FEAT-8c2e32c, ADR-819be48
