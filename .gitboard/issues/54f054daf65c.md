- **Goal:** prepare core for per-user hosting without changing any local behaviour.
- **Includes:** an explicit resolver context (registry source and clone directory) instead of process-global `userDirs()`; hardened `runGit` defaults (no global or system config, hooks disabled, protocol restrictions, timeouts, allow-listed environment, no user value in `GIT_SSH_COMMAND`, option-injection validation of URLs, hosts and branch names); HTTPS remotes with an allowed-hosts list and private-address blocking, only in hosted mode; hosted clone options (treeless, cone sparse checkout of `.gitboard/` in sparse-index mode); `core/git/sync.ts` (fetch, fast-forward, commit only `.gitboard/`, push, reset to remote, trailers `Gitboard-Op` and `Gitboard-Actor`; one commit per operation with message `chore(board): <operation> <ref>`, plus an opt-in skip-CI marker, off by default, enabled through a `commitSuffix` key in the repository config with a profile override, shown as a commented-out example in the `init` template); an opt-in `gitboard sync` for CLI users; a summary projection for board and backlog responses (see the dedicated issue).
- **Also:** a top-level `branch` key in the repository config with a `validate` check (absent or equal to the branch it is on, and a warning when issue files exist on a branch whose config points elsewhere) and a guard: write operations on a branch whose config has `branch` pointing elsewhere fail with an error naming the board branch and the worktree command (reads print a hint), so a write can never silently land where the hosted app does not look; split `repo.init` from registration in the local registry so hosted mode can init without registering.
- **Invariant (owner, 2026-11-21):** Gitboard changes nothing outside `.gitboard/`. `core/git/sync.ts` stages with an explicit `.gitboard` pathspec and, before committing and again before pushing, verifies that every changed path is under `.gitboard/`; otherwise it resets the clone and fails with an error. A test must show that an operation producing an outside change is rejected. Local-only operations that write elsewhere (skills installation) are not exposed by the hosted server.
- **Prerequisite:** the layout v2 story FEAT-6cb8a58.
- **Depends on:** phase 0 results; ADR-0aa6b23.
- **Validation milestone:** all existing tests and the parity test unchanged; new sync tests against a local bare remote.

- **Related:** FEAT-8c2e32c, ADR-819be48
