- **Goal:** board and backlog responses stop carrying every issue body. Today `boardFor` maps each card through `toIssue`, which includes the Markdown body, checklist and hash, so a response is O(total body bytes): about 1.5 MB per 1,000 issues at an assumed 1.5 KB each, 15 MB at 10,000.
- **Design:** an additive input option on `board.get` and `backlog.get` selecting `summary` or `full`, with `full` remaining the default so the CLI's `--json` output and agents are unaffected. The web app and the hosted server request `summary`: title, status, priority, labels, parent, rank, type, ref, checklist counts and the content hash (the backlog's inline edits send `expectedHash`). Bodies come from `issue.get`, which the drawer already uses. Operations stay declared once; the parity test covers both detail levels.
- **Why:** harmless on loopback, costly over a LAN or WAN to many users; also faster for the local app on large boards.
