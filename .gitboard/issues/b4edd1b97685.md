- **Question:** ADR-30abf7d fixes a flat issues directory. Is that acceptable at thousands of issues?
- **Why it matters:** GitHub's repository-limits page recommends at most 3,000 entries per directory. A tree entry costs 43 bytes (measured), so a flat tree is 430 KB at 10k and 4.3 MB at 100k issues; pushes stay tiny (measured thin packs of 272-392 bytes) because Git deltas the tree. Sharding changes the file format, breaks old CLIs and complicates merges.
- **Options:** Keep flat; shard by id prefix in a `version: 2` format with readers that accept both; per-project subdirectories.
- **Recommendation:** Keep flat for now and treat 3,000 issues per repository as the decision trigger. Design a reader-compatible v2 layout before general availability, since it is a format decision.
