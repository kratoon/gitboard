## Problem

`npm run build` prints a warning from the web build:

```
dist/web/assets/index-DpTf-F_s.js   582.36 kB │ gzip: 175.73 kB

(!) Some chunks are larger than 500 kB after minification. Consider:
- Using dynamic import() to code-split the application
- Use build.rolldownOptions.output.codeSplitting to improve chunking: https://rolldown.rs/reference/OutputOptions.codeSplitting
- Adjust chunk size limit for this warning via build.chunkSizeWarningLimit.
```

The whole app is one 582 kB script (176 kB gzipped). The app is served from the user's own machine, so the size matters little, but the warning shows on every build and publish.

## Steps to reproduce

1. Run `npm run build` (vite 8, 388 modules).
2. See the warning from `build:web`.

## Expected

A build with no warning, without hiding a real regression.

## Options

- Split vendor code (`react-markdown` with `remark-gfm` and `rehype-sanitize`, and `@dnd-kit`) into its own chunks with `build.rolldownOptions.output.codeSplitting`, or load the Markdown renderer with a dynamic `import()` since it is only needed once an issue is open.
- Raise `build.chunkSizeWarningLimit` with a comment saying why. Simplest, but it would also hide future growth.
- Check what makes up the bundle first, to see if a large dependency can be avoided.
