## Goal

Write the UI design down in the repository, so agents (and people) building the web app follow the same conventions without being told in every prompt. Today they live only in chat history and in scattered CSS.

## Approach

A design guide in the repository, linked from the instructions agents already read.

- [ ] `docs/design.md`: a short, living guide. Rules and the reason for each, with the code that implements it, not screenshots.
- [ ] `AGENTS.md`: one line telling agents to read `docs/design.md` before changing the web UI, and to update it when a convention changes.
- [ ] README keeps the vocabulary (Concepts table); the guide links to it instead of repeating it.
- [ ] Design tokens stay in `src/web/styles.css` (`:root` variables) as the single source of truth; the guide names them but does not copy values.
- [ ] A small ADR that records the decision to keep the guide in `docs/design.md`, so it is not replaced silently.

## What the first version should cover

Taken from decisions already made in FEAT-130c757:

- Terms: project key, issue key (ref), preview link, drawer and issue page (see the README Concepts).
- Navigation: issue pages at `/repos/<slug>/issues/<issue key>`; the drawer stays; plain clicks stay in the app, Cmd/Ctrl-click opens a new tab.
- Links: an issue key found in text is shown as `KEY: title`, outlined in light grey, blue border on hover, no underline. Standalone issue keys are plain links. A title that is a link keeps the text colour and only underlines on hover.
- Layout: the issue page is a content card plus a side card with the fields; the drawer stacks them.
- Editing: fields read as text and become dropdowns on click, with a hover highlight; label add is a chip that turns into an input.
- Actions: secondary actions live in the `⋯` menu; destructive actions ask for confirmation in a modal.
- Tables: configurable columns, no wrapping badges, horizontal scroll, draggable column widths remembered in the browser.
- Colour: type colours (epic purple, story green, task blue) and priority colours; light and dark themes both supported.
- Words: say "issue key", never just "key"; "Ref" is the short form.

## Alternatives considered

- **ADR only:** good for why, but a decision log is hard to scan for the rule that applies right now.
- **Design tool (Figma) only:** not readable by agents working in the repository.
- **Storybook or a component gallery:** shows the components, costs a build and a dependency, and still needs the rules written down.
- **Comments in the CSS:** close to the code, but invisible to anyone not reading that file.
