- **What:** a profile stored in a Git repository the user controls (`profile.yaml`, same schema as the local profile file), read and written through the sync manager, so settings survive losing the instance and are hand-editable; plus sharing the repository list between the local app and the hosted app: the profile lists repositories by remote URL, the local app maps each remote to the matching local clone (found with `git remote get-url origin`, canonicalised), the hosted app creates its own clones.
- **Why deferred:** the MVP keeps one local profile file on each side. Everything the MVP needs works from a file; a Git-backed profile adds a second write path and a bootstrap question (where the profile's own location lives).
- **Prepared for in the MVP:** a profile schema that works for both backings; no secrets and no machine paths in the profile; remotes stored in canonical form.
- **Open:** profile failure must not break board access (fall back to the last good copy); conflicts on `profile.yaml`; how the local CLI adopts it (`gitboard profile`).
