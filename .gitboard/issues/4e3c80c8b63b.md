- **Problem:** Typing an issue key such as `FEAT-6930f51` (or `BUG-abc1234`) into the search box, or passing it to `gitboard issue list --search`, returns no results, although the same reference works everywhere else (`issue show`, `--parent`).
- **Steps to reproduce:**
  1. Run `gitboard issue list --search FEAT-6930f51`, or type `FEAT-6930f51` into the web UI's search box.
  2. No issue is listed. Searching the bare short id `6930f51` does find it.
- **Expected:** The issue `FEAT-6930f51` is found. A reference of the form `KEY-shortid` should match, as should a bare key.
- **Cause:** `listIssues` in `src/core/issues/service.ts` matches the query only against `title\nbody\nid`. The project key is never part of that haystack, so the `KEY-` prefix breaks the match.
- **Suggested fix:** Also match the project key and the full reference (`${project}-${id.slice(0, 7)}`) in the haystack, and add a test for both the CLI filter and the web search.
- **Resolution:** The haystack now also contains `${project}-${id}`, so a `KEY-shortid` reference of any length matches, as does the bare key. The web search uses the same `listIssues` filter, so it is fixed too. Test: `search` in `tests/core/issues.test.ts`.
