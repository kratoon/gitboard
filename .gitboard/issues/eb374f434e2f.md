- **What:** a bounded per-repository fallback for repositories whose rulesets reject unsigned pushes: create the commit through the provider's content API so the provider signs it, or sign with a key the remote trusts (viability for an app identity is unverified).
- **Why deferred:** the MVP shows such repositories read-only with the reason. Build only if the Phase 0 spikes or real use show the case is common. It would be a per-repository exception with provider-specific code and API quotas, not a return to an API-first design.
