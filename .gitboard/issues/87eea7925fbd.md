- **Question:** One commit per operation or per batch? What message and trailers? How do we avoid triggering code CI on every issue move?
- **Why it matters:** Every write is a commit on the Gitboard branch: history growth, CI cost and attribution all follow from this.
- **Options:** Per-operation commits; squashing bursts into one commit; a skip-CI marker; path filters on the customer's CI.
- **Recommendation:** Per-operation commits with message `chore(board): <op> <ref>` and trailers `Gitboard-Op` and `Gitboard-Actor`; a configurable skip-CI marker, off by default; document path filters. Squashing only becomes relevant under sustained heavy automation (each commit is roughly 0.4-1 KB of pack data, an estimate).
- **Related:** FEAT-8c2e32c, ADR-0aa6b23
- **Decision / date:** 2026-11-21. One commit per operation, no squashing. If that is too noisy for a team, the answer is to move the board from the default branch to a dedicated branch (`branch` key, FEAT-0a956bc), not to change commit granularity. A skip-CI marker is **off by default**: Gitboard never changes how a team's CI behaves unless asked. To enable it, set the top-level `commitSuffix` key in the repository config (for example `commitSuffix: "[skip ci]"`, a string appended to the commit subject; another string suits another CI system), or override it per user and per repository in the profile (resolution order: profile, repository config, none). The template written by `init` contains the key as a commented-out example, so the option is discoverable in the config file. Key name is a proposal. GitHub documents `[skip ci]`, `[ci skip]`, `[no ci]`, `[skip actions]` and `[actions skip]` for `push` and `pull_request` workflows, and warns that workflows skipped by a commit message leave their checks "Pending", which blocks a pull request that requires them. A `skip-checks: true` trailer also works but must be the last trailer, so the subject suffix is used. Path filters in the CI configuration remain an alternative. Commit message `chore(board): <operation> <ref>` with trailers `Gitboard-Op` (idempotency key) and `Gitboard-Actor`; author is the acting user. The message and trailer names are proposals, open to change when `core/git/sync.ts` is written (Phase 1).
