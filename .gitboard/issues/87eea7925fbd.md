- **Question:** One commit per operation or per batch? What message and trailers? How do we avoid triggering code CI on every issue move?
- **Why it matters:** Every write is a commit on the board branch: history growth, CI cost and attribution all follow from this.
- **Options:** Per-operation commits; squashing bursts into one commit; a skip-CI marker; path filters on the customer's CI.
- **Recommendation:** Per-operation commits with message `chore(board): <op> <ref>` and trailers `Gitboard-Op` and `Gitboard-Actor`; a configurable skip-CI marker, off by default; document path filters. Squashing only becomes relevant under sustained heavy automation (each commit is roughly 0.4-1 KB of pack data, an estimate).
- **Related:** FEAT-8c2e32c, ADR-0aa6b23
- **Decision / date:** 2026-11-21. One commit per operation, no squashing. If that is too noisy for a team, the answer is to move the board from the default branch to a dedicated branch (`branch` key, FEAT-0a956bc), not to change commit granularity. A skip-CI marker is **on by default**: the text `[skip ci]` is appended to the commit subject (`chore(board): <operation> <ref> [skip ci]`). It is configurable and can be turned off per repository in the repository config, and overridden per user (and per repository) in the profile; resolution order profile, repository config, default. Proposed shape: one top-level key `commitSuffix` (a string; default `[skip ci]`; an empty string or `false` turns it off; another string suits another CI system). Key name is a proposal. GitHub documents `[skip ci]`, `[ci skip]`, `[no ci]`, `[skip actions]` and `[actions skip]` for `push` and `pull_request` workflows, and warns that workflows skipped by a commit message leave their checks "Pending", which blocks a pull request that requires them: the reason for the off switch. A `skip-checks: true` trailer also works but must be the last trailer, so the subject suffix is used. Path filters in the CI configuration remain an alternative. Commit message `chore(board): <operation> <ref>` with trailers `Gitboard-Op` (idempotency key) and `Gitboard-Actor`; author is the acting user. The message and trailer names are proposals, open to change when `core/git/sync.ts` is written (Phase 1).
