- **Question:** How does the instance hold each user's Git credentials, protect them, and verify SSH host keys?
- **Why it matters:** Credential handling is the highest-impact code in the product. It reverses the current rule that Gitboard never stores credentials (ADR-9d88632).
- **Options:** Credential kinds: app-generated ed25519 SSH key per user (public key shown to add at the remote), user-supplied HTTPS token, or both; an opt-in shared team credential for small setups. Protection: encrypted at rest (AES-256-GCM) with a master key from an environment variable or key file kept outside the data directory; decrypted only for one git call (memory or 0600 tmpfs file). Host keys: instance-managed `known_hosts`, trust on first use confirmed by an admin or per user, then strict checking.
- **Recommendation:** Both credential kinds, per-user by default; the shared credential only as an explicit opt-in mode. Master key outside the data directory. Admin-confirmed trust on first use. Verify on real NAS operating systems in the Phase 0 spikes.
- **Related:** FEAT-8c2e32c, ADR-87400e0
