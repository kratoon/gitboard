- **Question:** Does each user get an independent managed clone of each repository, or one shared bare object store per remote with a `git worktree` per user?
- **Why it matters:** Disk and fetch duplication versus credential isolation and locking complexity. With a shared store, objects fetched with user A's credential become readable through user B's worktree unless access is proven first.
- **Options:** (1) Independent clone per (user, repository), blobless with cone sparse checkout of `.gitboard/`. (2) Shared bare store per remote plus per-user worktrees (a worktree cannot check out a branch another worktree has; use a per-user local branch). (3) One shared clone with a service credential (loses per-user identity).
- **Recommendation:** Option 1 first. Typical clones are a few MB, so 50 users x 50 repositories is about 7.5 GB (assumption). Move to option 2 only if the Phase 0 spikes show duplication hurts, with a per-user access proof (authenticated fetch or ls-remote) before any worktree is created or updated. Temporary worktrees remain the tool for a future PR mode.
