**As a** developer using Gitboard, **I want** to attach GitHub pull requests, commits and other external items to an issue, **so that** I can see from the board which code changes implement it and jump straight to them.

## Acceptance criteria

- [ ] An issue can hold a list of links. Each link has a `kind`, a `url` and an optional `title`. They are stored in the issue's front matter, so they stay readable without Gitboard and merge cleanly.
- [ ] Supported kinds: `pr` (GitHub pull request), `commit`, `issue` (GitHub issue) and a generic `url`. The kind is detected from the URL (`/pull/<n>`, `/commit/<sha>`, `/issues/<n>`) and can be overridden.
- [ ] A commit may also be given as a bare SHA, resolved against the repository's `origin` remote when it is a GitHub URL.
- [ ] CLI: `gitboard issue link <ref> <url|sha> [--kind --title]`, `gitboard issue unlink <ref> <url|sha>`, and links included in `issue show` and in `--json` output. Linking the same target twice is a no-op.
- [ ] The CLI and agent skill stay at parity with the UI (no UI-only operation), and the operation lives in `core`.
- [ ] Web UI: the issue drawer lists links with a kind icon and a short label (`#123`, `a1b2c3d`), opens them in a new tab, and lets the user add and remove links. Cards show a small link count.
- [ ] Optional: `gitboard issue create --link <url>` and a way to link the current branch's pull request (`gh pr view`) when `gh` is installed. Gitboard works fully without `gh` and without network access.
- [ ] Unknown or malformed URLs are rejected with a clear error; existing issues without links are unchanged.
- [ ] Tests cover URL parsing, link and unlink, the front matter round trip, CLI output and the server API. README and the agent skill document the new commands.

## Out of scope

- Fetching PR status (open, merged, checks) from GitHub. Links are static references; live status would need accounts, a token and network, which conflicts with the local-first scope.
- Automatically linking from commit messages or branch names, and any write to GitHub.

## Open points

- Should a `pr` link auto-move the issue (for example to `done` on merge)? Probably not, because Gitboard never talks to GitHub. Raise it as a question (label `question`) if wanted.
- Field name and shape (`links:` list of objects vs. plain URL strings) should be settled in an ADR before implementation.
