- **Goal:** `gitboard serve` for several users on one instance.
- **Includes:** reading both issue layouts and an explicit "upgrade layout" action for writers (never migrating on read);  board-branch resolution (profile override, repository `branch`, default branch); a "not enabled" state and an explicit enable action that runs `repo.init` as a commit, or creates a dedicated orphan branch;  GitHub login through the generic OAuth2/OIDC core and the provider adapter interface; named-identity allow-list with pending queue in `users.json`; admin commands inside the container; sessions; encrypted storage and refresh of OAuth tokens (single-use refresh serialised per user); internal user ids and the identity/connection split;  per-user managed clones; per-clone lock, commit, push, retry by re-executing the operation; adaptive polling and cross-user notification; SSE; instance-local profile; container image.
- **Depends on:** phase 1; decisions on clone layout, authentication, credentials, settings split, board branch.
- **Validation milestone:** two users on one instance and one remote see each other's edits within seconds; an external `git push` appears via polling; killing the process during a write loses nothing that was acknowledged; user A cannot reach user B's repositories.

- **Related:** FEAT-8c2e32c, ADR-819be48
- **Code areas:** `src/server/security.ts` (configurable public URL for Host/Origin checks, CSRF for cookie auth; loopback `start` keeps today's behaviour); `src/server/index.ts` (a second server mode with auth middleware and per-user resolution, reusing `watch.ts`); `src/web` (login screen, preferences through `GitboardClient` instead of `localStorage`).
