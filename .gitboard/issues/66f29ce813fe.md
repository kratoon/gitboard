## Context

Issues are one file each in a single flat directory, `.gitboard/issues/<id>.md` (ADR-30abf7d). GitHub's repository-limits page recommends at most 3,000 entries per directory. A tree entry costs 43 bytes (measured), so a flat tree is 430 KB at 10k and 4.3 MB at 100k issues; pushes stay small because Git deltas trees (measured thin packs of 272-392 bytes). Repositories already use the flat layout. The hosted app would add many writes and larger boards, so the format is easiest to change now. Any change must not break existing repositories or silently hide issues from older tools.

## Decision

1. **The layout follows the config `version`.** Version 1 is the flat layout, unchanged. Version 2 stores an issue at `.gitboard/issues/<first two hex characters of id>/<id>.md`. The path remains a pure function of the immutable id, so changing project, parent or status never relocates a file (the principle of ADR-30abf7d). Shard width is fixed at two characters (256 directories, about 390 files per directory at 100k issues, uniform because ids are random).
2. **Readers accept both layouts** in either version. If an id exists in both places the sharded copy wins; `gitboard validate` warns when the two differ and when flat files remain in a version 2 repository.
3. **Writers never write the sharded layout in a version 1 repository.** In a version 2 repository, updating an issue that is still flat writes the sharded path and removes the flat copy, so repositories converge.
4. **New repositories** created by `init` start at version 2.
5. **Migration is explicit,** never triggered by a read: `gitboard migrate` (and an "upgrade layout" action in the hosted app for users with write access). It moves the flat files and bumps `version` to 2 in one commit, as its own operation, changing only `.gitboard/`. It is idempotent and stops if an id exists in both places with different content.
6. **Every CLI command in a version 1 repository warns** that migration is available (stderr in text mode; in `warnings` in `--json` mode).
7. **Older CLIs fail loudly on version 2**, because the schema accepts only `version: 1`; the version bump and the file moves are in the same commit, so no state exists in which an old CLI silently shows an empty board.
8. All path construction goes through one function.

## Alternatives considered

- **Stay flat:** simplest; exceeds the provider's recommendation beyond 3,000 issues and leaves a harder migration for later.
- **Migrate automatically on first load:** a read would write; read-only users and protected branches cannot push the change; a large noisy commit of renames; every older CLI breaks for the whole team as soon as one person loads the repository; parallel migrations must produce identical results. Rejected.
- **Migrate each issue when it is next touched:** small diffs, but older tools see a partial board silently. Rejected.
- **One-character shards (16 directories):** reaches 3,000 per directory at about 48k issues. **Three characters (4,096 directories):** many mostly empty directories and slow listing for small repositories.
- **Per-project directories:** the project is mutable, so changing it would move the file.

## Rationale

Version-gating makes the change opt-in per repository, keeps reads side-effect free, and turns the unavoidable incompatibility with older tools into a clear error at a known moment.

## Consequences

- Listing a version 2 repository reads up to 256 directories plus the flat one (more directory reads for small repositories).
- Merging a branch that edited a flat file after the repository migrated leaves a stale flat copy; validate warns.
- Documentation, the agent skill and the README issue-format section change when this ships.
- Older CLI versions cannot read migrated repositories; users upgrade.

## Scalability implications

Tree objects per directory stay small (about 17 KB at 100k issues); the provider's per-directory recommendation is respected up to about 700k issues.

## Open questions

- None blocking. Whether a future version drops flat reading is not planned.
