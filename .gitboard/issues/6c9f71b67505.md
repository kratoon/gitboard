## Context

Repository settings (projects, columns, views) lived in `.gitboard/config.json`. JSON cannot hold comments and
is easy to break by hand with a trailing comma, yet this file is meant to be read and edited by people, and
every issue already starts with a YAML frontmatter block. YAML is also already a dependency.

## Decision

**YAML is the default config format, and JSON is still fully supported.**

- **Files.** New repositories get `.gitboard/config.yaml`. Gitboard also reads `config.yml` and `config.json`.
  Exactly one config file must exist: with two, commands fail with `INVALID_CONFIG` naming both, and
  `gitboard validate` reports it. Gitboard never guesses between them.
- **The format never changes by accident.** Updates are written back into the same file in the same format.
  - JSON is rewritten as two-space JSON, as before.
  - YAML is edited in place: comments, blank lines and layout survive. Lists whose items can be recognised
    (columns and projects by `id`/`key`, views by value) keep untouched items and their comments when items are
    added or removed; reordering a list rewrites that list.
  - The result is checked against the requested config. If a YAML edit cannot reproduce it exactly, the file is
    regenerated (losing comments) rather than ever written wrong.
  - A file whose content would not change is not rewritten.
- **Converting.** `gitboard config convert [--to yaml|json]` (default `yaml`) moves a repository to the other
  format. The new file is created before the old one is removed, it is idempotent, and YAML comments do not
  survive a conversion to JSON. It is also available over HTTP.
- **One schema for both.** The same settings, validated the same way. YAML is read as YAML 1.2, so words like
  `yes` and `no` stay strings; values that would look like numbers are quoted when Gitboard writes them.
- **This repository** was converted with the command above.

## Alternatives considered

- **TOML:** another parser and a format unlike the issue files.
- **YAML only:** breaks existing repositories and people who prefer JSON.
- **Choosing the format in a per-user setting:** it would differ between machines for the same repository.
- **Converting automatically on the first write:** a surprising diff nobody asked for.

## Consequences

- Hand-edited configs can carry comments explaining why a column or view is set.
- Old `config.json` repositories need no action and do not gain a second file.
- Comments are only kept in YAML, and reordering a list loses comments inside it.
- The README and the examples in earlier ADRs show JSON; they remain valid.
