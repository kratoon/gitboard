## Context

Settings have different owners. Project definitions, columns and views belong to the repository and are shared. A user's repository list, preferences and personal views belong to that user (today: `repos.json` in the user config directory and `localStorage` in the browser). A multi-user instance must show each user their own projects based on their own settings.

## Decision

1. Settings have four owners, and secrets never go in Git:

| State | Location | Versioned in Git |
|---|---|---|
| Issues, projects, columns, views offered, Gitboard branch (`branch`), skip-CI marker (`commitSuffix`) | repository `.gitboard/` (shared) | Yes |
| Repository list and remotes, per-repository `branch` and `commitSuffix` overrides, visible projects, default repository, view and theme, personal saved views, commit identity | profile | No in the MVP |
| SSH keys, tokens | instance credential store | Never |
| Accounts, roles, session secret | instance data directory | No |
| Listen address, public URL, GitHub App credentials, limits, allowed remote hosts, master key location | instance config file or environment | No |

2. A **profile** holds the settings of one workspace of one user. The MVP has one workspace, `default`, so one profile per user.
3. The MVP profile is an **instance-local file**, on each side: the hosted instance has its own, and the local app keeps its registry (`repos.json`) and browser preferences. Its schema works for a local file and for a later Git-backed profile: no secrets, no machine paths, remotes in canonical form. A malformed profile falls back to the last good copy and never breaks board access.
4. A repository entry may carry a `branch` that overrides the repository's own `branch` for that user (resolution: profile, repository config, default branch). It is the bootstrap for repositories whose default branch is protected. The UI shows the Gitboard branch and warns when it differs from the repository's setting.
5. Personal saved views live in the profile; shared saved views, if built, live in `.gitboard/config.yaml` (FEAT-cd7b875).

Illustrative profile content (not a final schema):

```yaml
version: 1
identity: { name: Alice, email: alice@example.org }
default: web
preferences: { theme: dark, view: backlog }
repos:
  - name: web
    url: https://github.com/acme/web.git
    branch: main
    projects: [WEB, ADR]
savedViews: []
```

## Alternatives considered

- **A Git-backed profile in the MVP, shared between the local and hosted apps:** versioned and portable, but a second write path and a bootstrap question. Deferred (FEAT-31d4843).
- **Per-user settings only in the instance's account store:** no portability and not editable. Rejected.
- **Everything in the repository config:** forces personal preferences on the team and cannot express per-user remotes. Rejected.
- **Browser `localStorage` (today):** not shared across devices and invisible to the server. Rejected for hosted mode.

## Consequences

- A new file format to specify and validate.
- Local and hosted apps keep separate repository lists until the Git-backed profile exists.
