## Goal

Let an issue reference other issues with a typed relationship, so related work, blockers and duplicates are visible from the board and the issue page. External links (PRs, commits, URLs) are a separate story: FEAT-e66cc63.

## Scope

- [ ] An issue can hold typed links to other issues: `relates to`, `blocks` / `is blocked by`, `duplicates` / `is duplicated by`. Stored in the issue's front matter by issue key, so they stay readable without Gitboard and merge cleanly.
- [ ] Store each link on one side only and derive the inverse when reading, so the two issues cannot disagree.
- [ ] Core: add and remove a link, validate that the target exists, reject self-links and duplicate links; adding the same link twice is a no-op.
- [ ] CLI: `gitboard issue link <ref> <type> <target>`, `gitboard issue unlink <ref> <target>`, and links in `issue show` and `--json`. The agent skill documents them (CLI and UI stay at parity).
- [ ] Web UI: a "Linked issues" section on the issue page grouped by type, each entry a preview link with its status; add and remove from the page. Cards show a small marker for blocked issues.
- [ ] Decide the behaviour for links to issues in another project of the same repository (allowed, shown by issue key) and in another repository (out of scope for now).
- [ ] Deleting or moving an issue does not leave dangling links silently: show them as unresolved and offer to remove them.
- [ ] Tests for core, CLI, server API and the front matter round trip; README and skill updated.

## Notes

- Terms: see the README Concepts table (project key, issue key, ref).
- Field name and shape (a `links:` map by type vs. a list of objects) should be settled in an ADR together with FEAT-e66cc63, so both stories share one design.
- Out of scope: automatic status changes from links (for example closing a duplicate), and a dependency graph view. Split those into their own issues.
