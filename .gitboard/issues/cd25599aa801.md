- **Goal:** deliver a self-hostable, multi-user Gitboard server (`gitboard serve`) for any Git remote, with per-user credentials and a versioned per-user profile. Decisions are in ADR-819be48, ADR-0aa6b23, ADR-fe71de9, ADR-87400e0, ADR-7d58e8b; open questions are the linked "Hosted:" issues. Umbrella: FEAT-8c2e32c.
- **Open questions:** FEAT-02f3376, FEAT-26430a6, FEAT-94dfdce, FEAT-3658790, FEAT-0a956bc, FEAT-cf759ba, FEAT-926a35e, FEAT-87eea79, FEAT-b4edd1b, FEAT-f5a9856, FEAT-61ef959
- **Findings in the current implementation that shape the work:**
  - Every operation scans every issue file (`snapshot()` in `src/core/issues/service.ts`), including single-issue operations.
  - Several operations write more than one file sequentially: rank rebalancing, deleting an issue with `--unlink-children`, column remapping. A Git commit makes them atomic.
  - Concurrency control is optimistic by content hash (`expectedHash`) and writes are minimal key patches, so re-running an operation against a newer file merges edits to different fields.
  - The registry and managed-clone directory come from process-global `userDirs()`; `runGit` already takes per-call environment.
  - Remotes are SSH-only today and Gitboard never stores credentials.
  - Board and backlog responses include every issue body (about 1.5 KB per issue, an assumption).
- **MVP scope (decided 2026-11-21):**
  - One provider adapter, GitHub (as a GitHub App), around a generic OAuth2/OIDC core; the user's OAuth token is the Git credential.
  - Login only for named identities (allow-list) in `users.json` on the data volume; unknown identities wait in a capped, expiring pending queue. All admin actions are commands run inside the container; no admin web UI, no local passwords, no break-glass account.
  - A random internal user id per user; login identities and forge connections are separate records; one workspace per user (`default`).
  - Independent clone per (user, repository): treeless, cone sparse checkout of `.gitboard/` in sparse-index mode.
  - Docker is the only supported deployment, with the requirements, risks and quotas of ADR-87400e0.
  - Per-user profile as an instance-local file (per workspace), schema ready for a Git-backed backing.
  - Adaptive polling for remote changes; SSE to browsers.
- **Deferred (not MVP):** tracked in the epic FEAT-43d54b1.
- **Phases:** each is a child story, in order. Every phase leaves the local CLI and local web app working and byte-compatible (the parity tests are the guard).
